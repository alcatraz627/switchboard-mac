### Plugs (Home tab)

Reading the keys from the Lifelong Smart app on the phone did not work: the
phone is not rooted, so adb cannot read the app's private data.

Explored 2026-09-29, listening only. The three plugs decode (with Tuya's public
broadcast key) as one product (`productKey keyjup78v54myhan`), **protocol 3.4**,
already bound to a cloud account: .6 `d71767b54e44bcdf7aon6h`, .7
`d740139ff14a82a71esvq2`, .8 `d739196c2521acde50m6se`. Protocol 3.4 signs every
local command with the plug's own 16-character local key, so the keys are
needed once, whatever the route. The owner does not want a developer account,
and the plugs are paired in **Lifelong Smart**, a branded Tuya app.

1. **QR login with the Smart Life app** (recommended). Tuya's
   `tuya-device-sharing-sdk`, which Home Assistant uses, logs in by a QR code
   the owner confirms in Smart Life and returns every device with its local
   key. It covers only Smart Life and Tuya Smart accounts, so each plug moves
   there first: hold its button about 5 s until it blinks, add it in Smart
   Life. After one scan Switchboard talks to the plugs only on the LAN.
2. **Flash local firmware** (Cloudcutter to OpenBeken): no keys, no cloud, but
   model specific and can brick a plug.
3. Developer account (iot.tuya.com + `tinytuya wizard`): ruled out.

Build for route 1: a "Connect plugs…" button on the Home tab shows the QR code
in the panel; keys land in Switchboard's state folder (mode 0600). Control uses
`tinytuya` from a private Python environment under
`~/Library/Application Support/Switchboard/`. A `plugs.py` helper mirrors
`wiz.py`, and the Home tab gets a Plugs card under Lights.
